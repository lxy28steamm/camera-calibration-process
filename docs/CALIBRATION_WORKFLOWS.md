# 各类相机标定与复测（3.2.0）

启动：在工作台目录运行 `bash start-workbench.sh --no-browser`，打开终端显示的设备 IP 地址。默认无需登录。相机和本机路径都指运行服务的 Linux 主机，不是访问网页的另一台电脑。

## 选择入口

| 页面 | 用途 | 输入和输出 |
| --- | --- | --- |
| 相机复测 · 单目 | 固定已有内参，检查另采视频上的留出角点误差、覆盖、倾角与距离变化 | 通用单目 UVC 或离线视频 + 相应模型 YAML；HTML / JSON / CSV |
| 相机复测 · 双目 | 固定已有 K、D、R、T，检查重投影、跨目预测、极线偏差，比较标定记录 | 已适配设备或左右等宽拼接视频 + 标定 JSON / Kalibr YAML；报告与采样 |
| Dex / 单目标定 | 通用单目采集与重新求解；Dex 专用 Flash 读写 | 普通 UVC 也可使用求解；只有识别到的 Dex 可用其专有存储流程 |
| Ego-Lite 标定 | 沿用原设备双目链，求解相机—IMU 外参与时间偏移 | DepthAI 动态数据集、IMU 噪声参数；Kalibr YAML / PDF，外参备份写入回读 |
| Ego-Std 标定 | 从包含 YCTC SEI 的原始视频求解双目及相机—IMU 参数 | 原始 .h264、板尺寸与 IMU 噪声；bag、参数 YAML、PDF、CSV、日志 |

“任意相机”指可通过已支持的视频接口、文件格式和数学模型进入通用复测，不代表任意厂家的私有采集与存储协议都可自动使用。工业私有接口、独立双 USB 的同步及 RTSP 尚未适配。模型或分辨率不匹配会拒绝复测，不会悄悄缩放内参。

## Ego-Lite

1. 扫描并选择已连接的 Ego-Lite。读取设备内参后可先在相机复测页检查双目精度。
2. 在 Ego-Lite 标定页确认 AprilGrid：默认 6×6、tag36h11、ID 0–35、标签外黑边 55 mm、间隙 16.5 mm。固定板，移动整台相机，覆盖不同位置、距离和三个转轴，点击动态采集。沿用旧实现的左右图像 20 Hz、原始 IMU 200 Hz 和设备时钟；实际计数显示在页中。
3. 采集会先按 EEPROM 完整畸变参数去畸变，保存匹配该图像的零畸变 camchain，再固定双目链求解 IMU 外参。此流程不重新求解双目内参。IMU 静置采集只导出原始 CSV，后续需噪声分析；不能把静置采集成功视为已得到噪声参数。
4. 也可输入旧数据集所在路径，复制导入 `cam0/`、`cam1/`、`imu0.csv`、`camchain.yaml`。填写或导入当前设备的 IMU 噪声 YAML，确认依据，检查环境并运行 Kalibr。参考噪声值不自动适用于某一传感器。
5. 在本页下载结果和 PDF；选择结果后点击检查，核对目标设备、外参和时间偏移。只有显式勾选写入确认后才能备份 EEPROM、写入 IMU 外参并回读校验。双目内外参保留；时间偏移只保存在 YAML，未写入设备。写入前还会检查结果所用双目链与当前设备是否匹配。

没有相机时可以导入并处理已有数据集，采集和写入按钮禁用。Ego-Lite 数据位于 `data/ego_lite/`，与 Dex 分开。

## Ego-Std

1. 上传或填写运行主机上的原始 `.h264` 路径。必须包含 YCTC SEI、左右拼接画面及原始 IMU；普通 UVC 录像、转码后丢失 SEI 的 MP4 不能替代。当前交付代码提供导入标定，不提供设备端 H.264+SEI 录制程序。
2. 检查环境，选择本机 ROS / Kalibr，或已构建的交付 Docker 镜像。可依次只运行 SEI 提取、生成 bag、双目标定、相机—IMU 联合标定，也可一次跑到最后。
3. 网页默认使用已确认实物板 **55 mm / 16.5 mm**，图像比例 **1**。交付的 `sample/a01.h264` 示例使用 **35.2 mm / 10.56 mm**、图像比例 **0.5**，复现时必须改成对应值。标签尺寸写错会直接影响尺度和基线。
4. 图像尺寸来自实际解码，结果页面及 YAML 记录求解所用分辨率。例如原始每目 1920×1080，设为 0.5 后求解的是每目 960×540；该 YAML 不能直接当成原始 1920×1080 参数使用。本工具不会自动恢复或缩放参数。
5. 可导入已有双目 camchain，仅求解 IMU 外参与时间偏移。此时已有参数分辨率必须与本次处理尺寸严格一致。角点过滤阈值是求解过程的筛选参数，不是验收标准。
6. 完成后下载 YAML、PDF、统计 CSV、日志等。停止或失败时保留已完成阶段；在历史记录点击“按原配置继续到所选阶段”，复用原视频、板尺寸、模型、噪声和已有标定文件，忽略当前表单的新参数。原配置可在记录中展开核对；若最初只解析而未确认参数，继续求解前需勾选参数确认。要换配置应新建一次处理。
7. 点击“载入双目参数用于相机复测”，再使用独立采集的视频检查精度；几何复测仅支持其已实现的投影模型，其他模型须对应验证程序。写入能力来自另行提供的 `Write/` 程序，见下面的独立写入流程。

Ego-Std 数据位于 `data/ego_std/`。合入的厂家提取器、完整 Kalibr 源码归档、角点过滤与时间初值补丁、许可证位于 `src/ego_calibration/backends/ego_std_delivery/`。不依赖旧的下载目录；示例视频未打进迁移包。完整求解需要独立 ROS / Kalibr 环境，软件包只包含工作台和后端源码。

### Ego-Std 标定写入（Linux）

在运行主机接好相机，在顶部选择 **Ego-Std**，进入本页第 4 步：

1. 可先点击“读取并备份相机现有标定”，下载 `before.bin` 和 `before.json`；现有 Schema v2 还会导出 `before.yaml`。
2. 选择本流程联合标定结果，或导入完整 `camchain-imucam.yaml`。只完成双目标定、缺少两目 `T_cam_imu` 或 `timeshift_cam_imu` 的文件不可写入。最大 UTF-8 YAML 长度 8124 字节，连同头部与 CRC 总长最多 8192 字节。
3. 标定 / 固件 SN 留空会保留设备当前标定 SN；如设备未存 SN，填写设备对应的 1–32 位无空格 ASCII 编号。USB SN 与标定 SN 不要求字符串相同，不能把示例设备 SN 直接用于另一台相机。
4. 点击“检查参数、目标设备并备份”，对照设备现有参数和新参数，核实每目尺寸、内外参、基线、时间偏移及目标相机。工具保持 YAML 原始尺寸与内容，不自动缩放；缩放求解得到的 960×540 参数不能当作 1920×1080 参数写入使用。当前未自动验证所有设备成像模式，需要操作者确认对应关系。
5. 勾选确认，点击“写入、激活并回读验证”。后端会再次核对物理 USB 身份、YAML 哈希和当前标定，持久化写前备份，再按厂商协议解锁、48 字节分块传输、提交、激活、CRC 校验和逐字节回读。期间禁止停止操作；相机预览会先关闭。结果只在完整回读一致后标记成功。
6. 下载 `readback.yaml`、`verified.bin`、`write-result.json` 及原始备份，再用独立数据复测。备份可供后续恢复，但本页不提供自动回滚或 Schema v1 恢复写入。传输失败时原协议会尝试中止尚未确认激活的事务；激活或回读失败时不能假设旧标定仍有效，应重新读取设备核实。

写入只适配 Linux V4L2、带 USB 序列号且支持厂商写入协议版本 1 的 Ego-Std，不借用 Dex/Sunplus 或 Lite/DepthAI 的接口。Schema v1/v2 现有标定均先完整备份；无法读出有效备份时拒绝写入。网页检查参数不是精度验收，也不能证明标定来自当前相机，需操作者核对来源。

厂商写入凭据只在运行主机配置，网页不接收、不显示凭据。将厂家提供的凭据单独保存为工作台 `config/std-write.secret`（仅当前用户可读，`chmod 600 config/std-write.secret`），然后通过 `bash start-workbench.sh --no-browser` 启动。该文件自动排除于 Git 和迁移包；移动到小主机后需单独安全配置一次。也可在 `config/local.env` 指定 `YCTC_XU_UNLOCK_SECRET_FILE=/绝对路径/std-write.secret`。直接通过 Python 运行时需设置同名环境变量。已有 `YCTC_XU_UNLOCK_SECRET` 环境变量仍兼容，但建议使用文件避免凭据向子进程环境传播。

写入不要求 ROS/Kalibr 运行环境；读取、参数校验和写入适配器已包含在迁移包。新协议源码及来源记录位于 `src/ego_calibration/backends/ego_std_write/`，原始凭据和命令文本不包含在包中。

## Linux 小主机运行环境

基础预览、读取、OpenCV 单目求解和几何复测参见 `LINUX.md`，不要求 ROS。Ego-Lite 联合求解和 Ego-Std 的 bag / 求解需要 ROS / Kalibr。

已安装环境：在 `config/local.env` 中设置 `CAMERA_KALIBR_SETUP=/实际路径/环境脚本.sh`，脚本负责激活环境、加载 ROS / Kalibr 并把 `devel/lib/kalibr` 或对应安装目录加入 PATH。也可使用 `CONDA_BASE`、`EGO_KALIBR_CONDA_ENV`、`EGO_KALIBR_WS`。更换主机必须重新配置对应路径。

Ego-Std 可选 Docker：先在小主机安装 Docker，随后从工作台根目录执行：

```bash
CATKIN_JOBS=1 bash scripts/build-std-kalibr-docker.sh
```

脚本解包随附源码，使用交付 Dockerfile 构建 `kalibr-h264-imu-demo:20260805`。需要网络和较大的编译空间，首次耗时取决于主机。运行服务的用户须能访问 Docker。此镜像仅用于 Ego-Std；Ego-Lite 沿用已配置的本机或原有 Kalibr Docker 环境。本次验证使用本机环境，未实测 Docker 构建。

迁移整个发布目录即可保留代码和默认 `data/` 下的数据；Conda / ROS / Docker 镜像和厂家设备权限需在目标主机独立安装。原 Qt 界面仍可通过 `bash start-workbench.sh --desktop` 打开。
